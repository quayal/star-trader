# Lessons learned

Running log of findings, gotchas and improvements discovered while working on this project — after fixing a bug, hitting a surprising root cause, or learning anything worth remembering across sessions.

**Before starting non-trivial work or debugging something that feels familiar, skim this file for relevant prior entries.**

How to add a lesson:

- New entries go at the **top** of the list below (newest first), so skimming recent lessons doesn't require reading the whole file.
- Default to a short entry here: date, one line summarizing the lesson, and just enough context (what happened, what fixed it, why it matters) to be useful to a future reader who has no memory of this session.
- If the lesson needs more than a few lines — a non-obvious root cause, a multi-step investigation, something future debugging should be able to retrace — write the full account in `.ai/lessons/YYYY-MM-DD-slug.md` and link it from the one-line entry here.
- Don't edit or delete past entries to "clean up" — if a lesson turns out to be wrong or superseded, add a new entry saying so and leave the old one for context.

## Entries

- 2026-11-01: **`trader:functions-in-classes` reports Spring's `@DynamicPropertySource` companion function** (one parameter of a non-built-in type reads as a conversion). Don't suppress it: register test properties with a `DynamicPropertyRegistrar` `@Bean` in a nested `@TestConfiguration` class, which `@SpringBootTest` picks up (see `GameControllerTest`).
- 2026-11-01: **The ktlint Gradle plugin's incremental check can keep reporting a file you've deleted.** After deleting a scratch file used to prove a rule fires, `./gradlew build` still failed with that file's violations; `./gradlew build --rerun-tasks` passed. When ktlint names a file that no longer exists, rerun with `--rerun-tasks` before chasing it. CI starts clean, so it isn't affected.
- 2026-11-01: **Corrected by the creator: "prefer extension functions over object functions" meant member functions, not extensions.** I first read the creator's preference as "write `fun Game.toItem()` extensions" and built a rule for that. The creator's actual rule: call a function on the object you have and declare it in that object's class; extensions are only for library classes we can't edit. Where a member function would drag an adapter type into the domain (DynamoDB `AttributeValue`, a web DTO), the mapping goes on the adapter-side class as a constructor or method. Now engineering standards §5, enforced by `trader:functions-in-classes`.
- 2026-11-01: **To forbid something with ktlint, make a rule report it. Setting the rule to `disabled` only stops the check.** On 2026-10-15 `953cc98` "forbade" trailing commas by disabling ktlint's two trailing-comma rules. That stopped ktlint adding them but also stopped it reporting them, and the rule wasn't written in the engineering standards, so by 2026-11-01 there were 83 commas back across 30 files. The fix: the rules enabled with `ij_kotlin_allow_trailing_comma = false` (and `_on_call_site`). A style rule the creator sets goes in `.ai/engineering-standards.md` and gets a check that fails `./gradlew check`; for one ktlint doesn't have, add a rule to `ktlint-rules/`.
- 2026-10-31: **In zsh, never name a shell variable `path`.** zsh ties the lowercase `path` array to `$PATH`, so `path="pr-66/x.png"` inside a loop wiped the command search path and every later command (`gh`, `jq`, `base64`) failed with "command not found". This broke the `attach-image-evidence` upload loop from the tracker descriptor. Use another name (`rel`, `file`); the same goes for `cdpath`, `fpath` and `manpath`.
- 2026-10-31: **DynamoDB Local in Docker with a named volume must run as root, and the SDK client needs a call timeout.** With `-dbPath` on a fresh named volume, the image's own user can't write there; DynamoDB Local logs `unable to open database file` but still accepts connections and never answers, and an SDK client without `apiCallTimeout` waits forever, so `bootRun` hung silently after "Tomcat initialized". Fixed with `user: root` in `compose.yaml` and a 10 s `apiCallTimeout` in `DynamoDbConfiguration`. If startup hangs again, check `docker logs` of the DynamoDB container first.

- 2026-10-31: **Pass a PR or issue body with `--body-file <path>`, never `--body @<path>`.** `gh` doesn't read files from `@`, so PR #5's whole description became the literal text `@/tmp/pr5-body.json`. Its `Closes #3` was lost, so #3 stayed open for ten days after the work merged, and the dashboard spec was never moved to `implemented/`. After opening a PR, run `gh pr view <n> --json closingIssuesReferences` and check that the issue is listed.

- 2026-10-30: **Escape anything a player typed before it goes into `innerHTML`.** The Market rendered offer `playerName` raw, and the API accepts any text. Once E01-S03 put the session token in `localStorage`, that turned into session theft. Use `escapeHtml` from `static/js/html.js` (or `textContent`) for every server value in a template string.

- 2026-10-30: **A CSS `display` rule on an element beats its `hidden` attribute.** On the sign-in screen, `form { display: grid }` kept the hidden code step visible, so both steps showed at once. The JS state was correct, so only a screenshot caught it. Whenever a page toggles `hidden` on an element that has a `display` rule, add `[hidden] { display: none; }` for it.

- 2026-10-30: **If `RESEND_API_KEY` is set in your shell, local sign-in really emails the code.** `./gradlew bootRun` then fails for test addresses such as `ada@example.com` (Resend answers 422, and the page shows "We couldn't send the code"). To get codes in the server log instead, start it with `env -u RESEND_API_KEY -u RESEND_FROM_ADDRESS ./gradlew bootRun`.

- 2026-10-29: **Only ask the creator questions that change the design; give tunables a default.** The E03 spec marked "how long is the Bidding timer" as a blocking question, but it is one config value. Before marking a question blocking, ask: does the answer change the model, the engine, or a game rule? If not, pick a default, make it a setting, and don't ask. Correction from the creator.

- 2026-10-29: **Clicking through a prototype finds the states you cause, not the ones that happen to you.** Writing E03–E05 specs from revision 013 with a per-screen states checklist (empty, loading, error, no access, conflict, timeout, someone else stalls) found gaps that 13 revisions of clicking hadn't: no rule for an absent player in ordered steps (pick, jump slot, Resolve next), a roll with no offers on the winning side, and no end of game. Run the checklist before turning a prototype into stories.

- 2026-10-28: **Ask for a sketch before building a spatial layout from words.** "2:2:2 rows" meant a flat-topped hexagon ring, like a benzene ring, but was first built as a rectangular grid with bent edges, which cost a wasted prototype revision. When a layout is described in words (rows, ratios, "like X"), confirm the shape first with a 3-line ASCII sketch.

- 2026-10-28: **`./gradlew bootRun` serves static files from `build/resources/main`, not `src/`.** Edits to `src/main/resources/static/` don't show up on refresh until `processResources` runs. Fixed in `build.gradle.kts` with `bootRun { sourceResources(sourceSets.main.get()) }`. Note that an already-running server on port 3000, perhaps started by IntelliJ, may serve a different copy.

- 2026-10-28: **In this sandbox, auto mode blocks running remote packages via `npx`** (for example `npx uxproof@0.3.1`, which `om-ux-setup` uses). Use the skill's documented manual fallback (here `references/contract-format.md`) instead of retrying, and say in the output that the result was produced by hand.

- 2026-10-28: **The default shell is zsh, which doesn't word-split unquoted variables.** `for spec in "a 1 2"; do set -- $spec; ...` leaves `$1` holding the whole string. That produced wrong URLs and file names for headless-Chrome screenshots. Wrap such loops in `bash -c '...'`.

- 2026-10-18: Never `pkill -f` by the app's main class name (`StarTraderApplicationKt`) to stop a local `bootRun` — this repo is worked on from several worktrees at once, and the main class name is identical across all of them, so the pattern matches and kills *any* running instance, not just the one you started. Killed another worktree's dev server on port 3000 this way while manually verifying a UI change. Always capture and kill by the exact PID of the process you launched (`$!` / a PID file), never a name/pattern match, in this sandbox.

- **2026-10-15 — `git push`/`pull` over HTTPS fails in this sandbox until `gh auth setup-git` is run.** `gh` is pre-authenticated (browser/passkey login), but plain `git` doesn't use that login on its own — it tries legacy username/password auth, which GitHub no longer accepts, so pushes fail with errors like "could not read Username" even though `gh auth status` shows logged in. Fix: run `gh auth setup-git` once per sandbox. It writes **per-host** credential config (`credential."https://github.com".helper`, `credential."https://gist.github.com".helper`), not the generic `credential.helper` key — so `git config --get credential.helper` will look empty even after it's correctly set; check with `git config --get-all 'credential.https://github.com.helper'` or just test with `git fetch` instead.
