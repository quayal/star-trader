# Lessons learned

Running log of findings, gotchas and improvements discovered while working on this project — after fixing a bug, hitting a surprising root cause, or learning anything worth remembering across sessions.

**Before starting non-trivial work or debugging something that feels familiar, skim this file for relevant prior entries.**

How to add a lesson:

- New entries go at the **top** of the list below (newest first), so skimming recent lessons doesn't require reading the whole file.
- Default to a short entry here: date, one line summarizing the lesson, and just enough context (what happened, what fixed it, why it matters) to be useful to a future reader who has no memory of this session.
- If the lesson needs more than a few lines — a non-obvious root cause, a multi-step investigation, something future debugging should be able to retrace — write the full account in `.ai/lessons/YYYY-MM-DD-slug.md` and link it from the one-line entry here.
- Don't edit or delete past entries to "clean up" — if a lesson turns out to be wrong or superseded, add a new entry saying so and leave the old one for context.

## Entries

- **2026-11-23 — A new DTO field whose name contains a module's name trips the "another player's modules" privacy test.** `freePassengerSeats` on `you.ships` made `shouldNeverSendAnotherPlayersHullsModulesOrStats` fail on `doesNotContain("Passenger")`, though nothing leaked: the test searches the viewer's whole response text. Name such fields without a module's name (`freeSeats`), or the test will need the same cut-out as the catalogue.
- **2026-11-23 — A green `./gradlew check` without Docker skipped 137 tests, the HTTP and DynamoDB ones included.** Docker Desktop wasn't running, so Testcontainers skipped `GameControllerTest` (107) and the item store tests, and the build still said `BUILD SUCCESSFUL`. A change to a DTO or an item is only checked once those run. After a local check, count `skipped` in `build/test-results/test/*.xml` (it should be 0), or run `docker info` first and `open -a Docker` if it fails.
- **2026-11-23 — The privacy tests search the whole response text, so a public catalogue in `you` can trip them.** Once `you.invest` was sent in every phase, `shouldNeverSendAnotherPlayersOffers` (`"price":19`) and `shouldNeverSendAnotherPlayersHullsModulesOrStats` (`Flute`, `"modules"` counts) failed: the shipyard lists every hull and module, and factory prices can be 19. Nothing leaked. Those checks now cut the catalogue out first (`withoutCatalogue`). A new field that lists public game data under `you` will need the same.
- **2026-11-21 — A higher S/D means more supply, so prices tend to fall.** The story headlines first called the chips (+3) and food (+2) breakthroughs "demand up", reading R08's "a non-negative result picks the best BUY offer" as buyers being keen. The price table says otherwise: `SupplyDemand` maps a positive indicator to a negative price modifier. Before writing anything about which way a market moves, read `SupplyDemand.PRICE_MODIFIER_BY_INDICATOR`, not the offer-picking rule.
- **2026-11-21 — A screen added to `screenForPhaseChange` needs a link in the page too, or the phase change throws.** PR 171 made News a phase-change screen, but `render` in `index.html` mapped screens to links with its own object literal that had no `news`, so `link(game.id)` threw and nobody was taken to News. Only the playtest showed it, because the unit test covered the screen name and not the link. The map is now `phaseScreenLink` in `game.js`, tested for every screen a phase change can return; when a mapping lives in `index.html`, it isn't tested.
- **2026-11-20 — `GameControllerTest.shouldCollectOutputIntoAShipAndShowTheCargoOnlyToItsPlayer` is flaky.** It failed once in a full run (two ships offered as collect destinations instead of one) and passed when run alone. The game starts on real random starting systems, so both of a player's ships sometimes start at the factory's system. Pin the start with a fake picker if it fails again; don't chase it as a regression.
- **2026-11-20 — Game data that was only displayed can be wrong, so check it with the creator before giving it a mechanic.** `StarSystem`'s Port class, legal system and Planet security came from an early prototype. Nothing used them, so nobody noticed they were wrong until the smuggling spec made security decide landings, and the creator corrected every value (Beta Hydri's security is 10, not 1). The same goes for any table: the vault manual itself can contradict its own description (event E1's "subtract from your roll"). Before a spec makes a number matter, confirm the numbers.
- **2026-11-20 — `you.ships` (private) has no system or location; a ship's position is in the public `players[].ships`.** The new agent forms listed "Aboard Meridian (undefined)" because they read the viewer's private ship list, which only a browser walk showed. For where the viewer's ships are, read their own entry in `players`. Also: a stray `cat` with no input in a shell pipeline waits on stdin forever. Pass `< /dev/null` to long Gradle runs started from a script.
- **2026-11-19 — This shell can have `RESEND_*` variables set, and then a local `bootRun` emails real sign-in codes.** A browser walk's `POST /api/login/request-code` for a made-up address went to Resend instead of the log, because `RESEND_API_KEY` and `RESEND_FROM_ADDRESS` were in the environment. Before a walk, start the app with them unset (`env -u RESEND_API_KEY -u RESEND_FROM_ADDRESS -u AWS_REGION ./gradlew bootRun`) and check the code shows up in the log ("One-time sign-in code for …") before signing anyone in. Also: `bootRun` serves `build/resources`, so run `./gradlew processResources` after editing a static file mid-walk.
- **2026-11-19 — A dialog that should come after a notification card has to wait for it explicitly.** The landing dialog opened the moment a ship arrived, and the "You evaded an interception" card waited behind it, so the player chose where to land before learning they had evaded. `updateLanding` now holds back while an evaded card is unseen (`evasionFirst`), and the card's close opens the landing. The battle dialog likewise waits for the landing, the report and the cards, and their `close` handlers call `updateFight`. Each modal that can be pending at once needs its place in that order written down where it opens.

- **2026-11-19 — What one player may see is decided in the domain (`Game.viewFor` → `PlayerView`), never in a DTO.** Each confidential feature had been adding another `takeIf { player.email in … }` to `YouResponseDto`/`BattleDtos`, which made the R17/R29 rules invisible to domain tests (architecture review, finding 1). Now each part answers for its own data (`Resolution.awaitingTradeOf`, `Interception.asks`, `Battle.involves`), `Game.viewFor` assembles them, `PlayerViewTest` holds the other-player case for each, and the DTO only maps. A new private field goes on `PlayerView` with its negative case in `PlayerViewTest`; standards §13 row 0.
- **2026-11-19 — A Spring `HandlerMethodArgumentResolver` runs in parameter order.** Replacing each endpoint's `@RequestHeader` + `sessionFor` with a `Session` parameter could have turned a malformed body without a token from `400` into `401`: the header argument never failed, so the body used to be read first. The `Session` parameter goes last in every endpoint to keep that order.

- **2026-11-18 — Anything that should appear when a dialog closes must be triggered by that close, not left to the next poll.** The notification cards wait while the landing dialog or the battle report is open. After the report closed, nothing showed, because the game hadn't changed: the poll got a `304` and nothing rendered. The cards now re-check on those dialogs' `close` events. Since PR 159's 304s, "the next poll will redraw it" holds only when the game changed.
- **2026-11-18 — Initiative now rolls 2d6, and `FakeDice(vararg)` means 2d6 rolls; `Dice.d2` is gone.** The creator corrected R27 (bid + 2d6, every bid and roll public once Bidding closes). Since nothing else rolled d2, the port lost it, and `FakeDice`'s vararg constructor now feeds the 2d6 queue, so the ~70 tests that closed Bidding with `FakeDice(2, 1)` kept their order unchanged. A fake that answers every 2d6 with the same number (`JUMPS_SUCCEED`, `WholeGameTest`'s dice) ties every initiative roll among players with equal bids and would reroll forever: give one player a higher bid. Also, in a browser walk, `innerText` of anything inside a closed `<details>` is empty; read `textContent` or open it first.
- **2026-11-18 — A rule that depends on what happened earlier in a turn needs that history kept on the `Turn`, not only on the thing it started.** Playtest bug: interception tries were stored only on the `Battle` a successful try starts, so after a failed try the arriving ship staying in Space started an R80 battle with no tries, and returning fire at the ship that had tried cost reputation (R86). `Turn.interceptionTries` now keeps every try of the turn and `Battle.start` keeps those between its own ships. When a rule says "a ship that tried to…", check every path that can lead to the place it's checked, not just the obvious one.
- **2026-11-18 — With response compression on, `RestTestClient` (Apache HttpClient) leaks a pooled connection for every gzipped response a test doesn't read, and the 6th request hangs forever.** `GameControllerTest` stalled in `StrictConnPool.get` after `server.compression.enabled=true`: the many `.expectStatus()`-only checks never consumed the body, so connections weren't released. Browsers always read the body, so production is fine. The HTTP-level tests set `server.compression.enabled=false` in their `@SpringBootTest` properties; a compression check belongs in a test that reads the body.
- **2026-11-18 — Tomcat doesn't compress a response with a strong ETag.** With `server.compression.enabled=true` and Spring's `ShallowEtagHeaderFilter` on `/api/games/*`, `index.html` came back gzipped but every game poll didn't: the filter writes a strong ETag, and Tomcat's `noCompressionStrongETag` (on by default) skips compressing such responses. `isWriteWeakETag = true` on the filter gives `W/"…"` ETags; then both compression and `304 Not Modified` work. Check a poll's `Content-Encoding` with `curl -H 'Accept-Encoding: gzip' -D -`, not just a page's.
- **2026-11-18 — A rule that rolls a new die breaks every test whose `FakeDice` doesn't hand out that kind.** E13 made interception tries and some shots roll 2d6 for reputation, and 28 `GameBattleTest` cases failed with "FakeDice ran out of 2d6 rolls", though nothing they asserted changed. `FakeDice` keeps one queue per die kind and fails when one runs dry. When a rule starts rolling a new kind of die, give the affected test file a small `dice(…)` helper that supplies spare rolls of that kind, as `GameBattleTest` now does, instead of editing every call.
- **2026-11-18 — A gate on turn 1's Bidding touches every test that starts a game; chain a test helper with `.let` instead of rewriting fixtures.** E12's "place your connection points before done" broke ~75 tests (domain, DynamoDB and controller) at once, because nearly every fixture starts a game and signals done. Adding `START_DICE` to each `Game.start(…)` and appending `.let { ConnectionsPlaced(it).byEveryone() }` (a small test class, since ktlint forbids an extension on `Game` even in tests) was a mechanical script over the call sites; the controller tests got a `placeConnections(token, gameId)` helper in `startedGame`. The leftovers were real: log sizes and texts, and factory tests that the new cap (R84) now refuses. Also: `form { display: grid }` in `index.html` beats `[hidden]` on a form too, so a form that hides gets its own `[hidden] { display: none }` (`.raise-form[hidden]`), as for panels and buttons before.

- **2026-11-18 — A "seen" key built from a line's text brings a dialog back whenever the text changes.** The battle report keyed each line by its text, and the firer's line changes when the target places its hits ("wait for X to apply damage" → "X applied the damage"), so the report reopened for everyone after each placement. Key "already seen" by the event's identity (round, firer, target), and refresh the open dialog's text separately.
- **2026-11-17 — A headless Chrome from an earlier walk can still own the DevTools port.** The move-goods walk connected to `--remote-debugging-port=9333`, but a Chrome left running by a previous session already held it, so the script drove that browser's page (polling another game on a dead server) and every `getElementById` came back null. Before spawning Chrome, check the port is free (`curl -s -m 1 http://127.0.0.1:<port>/json` should fail) or pick an unused one, and `kill` your own Chrome when the walk ends. Also: a walk can seed state with the AWS CLI against its own DynamoDB Local (`docker run -p 8100:8000 amazon/dynamodb-local`, `aws dynamodb scan/put-item --endpoint-url http://localhost:8100`, keys `local`, region `eu-central-1`), bumping the item's `version`; in zsh pass `--endpoint-url` literally, since an unquoted `$VAR` holding two words isn't split.
- **2026-11-17 — The creator's vault notes can be wrong; a rule copied from one is a claim to check, not a fact.** E10 implemented a battle salvo as weapons + 2d6 and rockets as hull + module rocket values, both as the `ships and modules` note said. After play the creator corrected both: a salvo is weapons + **d6**, and rockets come **only** from modules (`.ai/specs/2026-11-17-battle-rockets-and-salvo-results.md`). With d6 a starting Clarinet tops out at 12, so the table's higher rows only matter for heavily armed ships. When a spec copies dice or numbers from a note, say so in the spec so a correction knows where to look.
- **2026-11-17 — Reading the standards didn't stop standards slips; placing each rule before coding and auditing the diff after does.** The battle round's rules (hit totals, rocket kills, overwhelmed ships) had been written in `Game.withRoundFired`, `BattleDtos` decided who may land from `battle.stage`/`battle.done`, and `Player` plus a DTO found a factory by comparing `system` and `goods` in four places, all after sessions that had read §8. The creator flagged `Salvo` sitting in the flat `game` package, and a design review found the rest. The fix is process, not memory: the `trader-implement` skill (placement table before code, a grep audit of the diff before commit). When a slip gets past it, add its pattern to the audit.
- **2026-11-17 — Don't name a shell variable `GID` (or `UID`) in a walk script.** zsh treats them as special: `GID=$(…)` tries to change the process's group ("failed to change group ID: operation not permitted") and the variable stays empty, so every later `curl …/games/$GID/…` hits a 404 that looks like an app bug. Use `GAME=` for a game id. Also: `POST /api/games` needs a body with `turns` (1–50); `{}` is refused.
- **2026-11-17 — Without agent-browser, a browser walk can drive headless Chrome over the DevTools protocol from Node.** `agent-browser` wasn't installed for the E10 walk; Google Chrome was. Spawning it with `--headless=new --remote-debugging-port=…` and talking to the page's `webSocketDebuggerUrl` with Node's built-in `WebSocket` gives `Runtime.evaluate` (fill and click forms, read `innerText`) and `Page.captureScreenshot`. Sign in by setting `starTrader.sessionToken` with `Page.addScriptToEvaluateOnNewDocument` before navigating; a `localStorage.setItem` evaluated after the first navigation didn't stick. Delete the `--user-data-dir` profile after `processResources`, or Chrome serves the old modules from its cache.
- **2026-11-17 — In zsh, `GID` (and `UID`, `EUID`) is a built-in integer variable.** `GID=$(…)` holding a game id failed with "bad math expression". Name shell variables for a game `GAME`. Separately, zsh doesn't word-split an unquoted `$VAR`, so `set -- $S` puts the whole string in `$1`.
- **2026-11-17 — Jumps roll dice now (R68), and `GameControllerTest` runs on real random dice.** A controller test that jumps must jump to a destination its ship is certain to reach (`certainDestination`, read from `you.ships[].jumpChances`; every starting ship has one, since crew B + Safe jump add 5 and every system has a route of base 7+), or it fails about 4 times in 10. Domain tests pass `JUMPS_SUCCEED` (every 2d6 a 2) unless they test the roll.

- **2026-11-17 — `checkTokens` reads `#128` in `index.html` as a colour literal.** A comment citing a PR number (`#128`, `#abc`, any 3/4/6/8 hex digits after `#`) fails `./gradlew check` as a colour outside `tokens.css`. In static files, write "PR 128" or name the story instead.

- **2026-11-17 — A screen redrawn only when the game changed can't show its own UI state.** `renderRunning` called `renderFleet` only `if (changed)`, i.e. when the polled game differed. E09's Sell button sets a page-local `pendingSale` and calls `render(lastGame, false)` — same game, so Fleet never redrew and the confirm step never appeared; unit tests couldn't see it, only the browser walk did. A screen with local state (a pending confirm, a busy flag) needs its own redraw key over the game data *and* that state (`shownFleetKey`), called on every render.

- **2026-11-17 — A form's status line that outlives its turn reads as current.** The offer form isn't rebuilt between polls, so "Offer placed: Buy FOOD at 12 HT…" stayed under the form into the next turn's Bidding. Only switching systems or a "Bidding has closed" refusal had ever cleared it. `updateOfferForm` now remembers the `game/turn` it last showed and clears the message and price error when that changes. Any persistent form that shows a success or error line needs the same per-turn reset.

- **2026-11-17 — The `AWS_REGION` trap of 2026-11-16 is closed for the tests.** The Spring tests now set `star-trader.dynamodb.region` to `DynamoDbLocal.REGION`, the region their own client uses, so an exported `AWS_REGION` no longer makes `LoginControllerTest.shouldKeepTheSessionAcrossARestart` look at tables that don't exist; `./gradlew build` passes with it set. A new `@SpringBootTest` that registers `star-trader.dynamodb.endpoint-override` must register the region too. A local walk still needs the same region as whatever reads its data (the `curl` half of that lesson stands).
- **2026-11-16 — `./gradlew test --tests '*SomeTest'` fails with "No tests found for given includes" in `:ktlint-rules`.** The filter is applied to every project's `test` task, and the `ktlint-rules` subproject has no test by that name, so the build fails before the root project's tests run. Name the task: `./gradlew :test --tests '*SomeTest'`.
- **2026-11-16 — `AWS_REGION` exported in your shell breaks `LoginControllerTest.shouldKeepTheSessionAcrossARestart` locally, and hides a walk's data from `curl`.** DynamoDB Local keeps a separate set of tables per access key and region. The app takes its region from `AWS_REGION` (`application.properties`), while the test's own client (`DynamoDbLocal.client()`) always uses `eu-central-1`, so with another region exported the test looks in an empty namespace: "Cannot do operations on a non-existent table". CI has no `AWS_REGION`, so it passes there. Run `env -u AWS_REGION ./gradlew check` locally. The same goes for seeding a browser walk with `curl` (lesson 2026-11-07): the `Credential=local/<date>/<region>/…` header must name the region the app runs with, or `GetItem` finds no table.
- **2026-11-16 — Check a hidden panel by what's on screen, not by `.hidden`.** E06-S08's `.infrastructure .panel { display: grid }` beat the `[hidden]` rule, so the Collect panel stayed visible after Confirm while `element.hidden` was `true` and every DOM check passed; only a screenshot showed it. This is the same gotcha as 2026-10-30 and 2026-11-04. When a container sets `display` on its panels, add `.container .panel[hidden] { display: none }` after it, and in a browser walk assert `offsetParent === null` and look at the screenshot.

- 2026-11-15: **`git checkout --theirs <file>` takes the whole file from the other side, not just the conflicting hunks.** Resolving #107's one conflict in `BACKWARD_COMPATIBILITY.md` this way silently dropped the rest of that PR's edits to the same file (the §7 rows for `players[].warehouses` and `players[].factories`, and the item list in "Required path"), and the build still passed because no test reads that doc. It surfaced a day later, in #104's work. To resolve one hunk, edit the conflict markers (or re-apply your hunks to the other side's file), then diff the result against both parents: `git diff HEAD -- <file>` and `git diff origin/main -- <file>` should show only what you meant to keep.
- 2026-11-10: **Don't add machinery to delay an effect the rules already make harmless.** E05-S06 first held market-position changes as "pending" until the next turn, which added a stored field, a turn-start hook and "from turn N" wording. The creator pointed out that each good resolves once a turn with its Dictator and Wholesalers fixed when it starts, so a position given at once can't affect the turn. Positions now change immediately. Check what the existing resolution order already guarantees before adding state for a rule like "takes effect next turn".
- 2026-11-08: **`./gradlew build` passed while `index.html`'s inline module script didn't parse, and every screen was blank.** No test imports that script, so a broken splice (a Python `str.index("});")` that matched an inner `});` first) went unnoticed until a browser walk. `src/test/js/index-html.test.mjs` now runs `node --check` on it. When editing `index.html` with a script, splice on unique markers, not on a closing brace pattern.
- 2026-11-08: **`node --test src/test/js/` (a directory) reports "tests 1, fail 1" on Node 22 instead of running the suite.** It tries to load the directory as one test file. That looks like a broken JS test when nothing is broken. Run `node --test src/test/js/*.test.mjs`, or `./gradlew jsTest`, which the build already runs.
- 2026-11-07: **Start a local walk's app with `RESEND_API_KEY=` (blank). The shell profile exports a real key, and `bootRun` picks it up.** During the E05-S03 walk, `/api/login/request-code` for `orion@example.com` went to Resend and came back `503` "We couldn't send the code" (Resend refused example.com). With a real address, it would have emailed someone. With the key blank, `ResendOneTimeCodeSender` logs "One-time sign-in code for … <email>: CODE" instead, and the walk reads the code from the app log: `RESEND_API_KEY= DYNAMODB_ENDPOINT_OVERRIDE=http://localhost:8100 ./gradlew bootRun --args='--server.port=3100 --spring.docker.compose.enabled=false'`.
- 2026-11-07: **To seed state the game can't reach yet (e.g. a Dictator position before E05-S06) in a browser walk, write it into DynamoDB Local with `curl`. No AWS CLI is needed.** DynamoDB Local doesn't check signatures, so any well-formed header works: `curl localhost:8100/ -H 'X-Amz-Target: DynamoDB_20120810.UpdateItem' -H 'Content-Type: application/x-amz-json-1.0' -H 'Authorization: AWS4-HMAC-SHA256 Credential=local/20261107/eu-central-1/dynamodb/aws4_request, SignedHeaders=host, Signature=0' -d '{"TableName":"star-trader-games","Key":{"id":{"S":"<game>"}},"UpdateExpression":"SET players[0].marketPositions = :p",…}'`. Read the item first (`GetItem`) to find the player's index. Use the walk's own DynamoDB container (lesson 2026-11-04), never the main checkout's.
- 2026-11-07: **With Docker stopped, `GameControllerTest` and the DynamoDB tests are skipped, and Gradle still says the build passed.** During E05-S01 a targeted run of `GameControllerTest` printed nothing and looked green; its XML report said `tests="49" skipped="49"`. Before claiming adapter or controller tests pass locally, check `docker info` (or `grep -h skipped= build/test-results/test/*.xml`); start Docker Desktop with `open -a Docker` if it's down.
- 2026-11-07: **agent-browser's `drag` doesn't start an HTML5 drag** (`draggable` + `dragstart`/`drop`): it moves the mouse, so the drop handler never runs and the walk looks like a bug. Check drag and drop by dispatching `new DragEvent('dragstart'|'dragover'|'drop', { bubbles: true, cancelable: true, dataTransfer })` through `eval`, and say in the evidence that a real mouse drag wasn't exercised. Separately: a button disabled during its own request loses focus to `<body>`; put focus back when the answer arrives.
- 2026-11-06: **When moving rules out of an aggregate root, don't let one part take another as a parameter.** My first pass had `Turn.placeOffer(player, …)` call `player.isDictatorOf`, to keep the old order of checks. That just moved a two-part rule from `Game` into `Turn` and made `Turn` depend on `Player`; an architect review caught it. A rule that needs two parts stays on the root as coordination (`turn.placeOffer(player.offer(…))`); the parts each own only their own data. Now a `CODE_REVIEW.md` check.
- 2026-11-06: **Don't scope a ktlint rule with an `.editorconfig` glob section like `[**/src/test/**.{kt,kts}]`.** Adding one, only to disable `trader:copy-only-in-own-class` for tests, made ktlint report "Unnecessary trailing comma" on test lines that had no comma. The new section disturbed how the `[*.{kt,kts}]` settings applied to those files. Skip test sources inside the rule instead (by `containingFile.virtualFile.path`, tested with `asFileWithPath`), and run `./gradlew build --rerun-tasks` after touching `.editorconfig`.
- 2026-11-06: **Corrected by the creator: an aggregate root isn't a place to write every rule.** `Game` was the right entry point and consistency boundary, but it had grown to 336 lines that copied ships, validated offers and bids, and did turn-order bookkeeping itself. The creator's rule: each part (`Ship`, `Player`, `Offer`, `Turn`) owns the rules about its own data, and `Game` only coordinates. This is now engineering standards §8. When adding a rule to `Game`, first ask which part's data it checks or changes, and put it there.
- 2026-11-04: **A fourth case of screen state that must be keyed by game: a `<select>`'s kept choice.** E04-S02's "Your next jump" keeps the chosen ship and destination across polls by rebuilding the options only when they change. Ship names (`Ship.NAMES`) and the board are the same in every game, so the lists' keys didn't change between games and a new game opened with the last game's ship and destination already selected. Only a browser walk across two games caught it. Key a kept form choice by game and turn too, not only by the option list.
- 2026-11-04: **agent-browser `open` with a URL that differs only by its `#hash` doesn't reload the page.** It's a same-document navigation, so a script changed since the last load (after `./gradlew processResources`) isn't picked up and the walk tests the old code. Run `location.reload()` through `eval` after changing a page.
- 2026-11-04: **A body grid that gains a row in a media query must redeclare `grid-template-rows`.** Below 700 px `index.html` stacks sidebar, top bar and main as three areas but kept `grid-template-rows: auto 1fr`, so the *top bar* got the `1fr` row and stretched to fill the viewport on any short screen (the new Game log, s04, showed a 283 px top bar on a phone). Fixed with `auto auto 1fr`. The same walk hit the `hidden`-vs-`display` gotcha a third time (`.game-log`); both were caught only by screenshots, so check a new screen at phone width and with its siblings hidden.

- 2026-11-04: **Screen state that outlives a poll must be keyed by game, not just turn or phase.** `index.html` is one page for every game, and its forms and top-bar messages are static markup shared across them. Three times a "Bidding has closed" state was keyed by turn number (or turn and phase) only, so it showed up in the player's next game at the same turn: the done message (fixed in #74 review), the bid form (#76) and the offer form (#77). Key such state as `${game.id}/${turn}`, and clear the typed values and message when the key is dropped.

- 2026-11-04: **The `hidden`-vs-`display` gotcha (2026-10-30) came back with `.btn`.** The top bar's "I'm done bidding" button had `hidden` set but stayed on screen, because `.btn { display: inline-flex }` wins. Again only a screenshot caught it, since the JS state was right. The rule is now in `docs/design-system.md` ("If… then use…"): any element that gets `hidden` and has a class that sets `display` needs its own `[hidden] { display: none; }`.

- 2026-11-04: **Running a second checkout locally: `bootRun` fails if another checkout's DynamoDB Local already holds port 8000.** Start a throwaway container on another port (`docker run -d --rm -p 8100:8000 amazon/dynamodb-local:3.3.2`) and run `DYNAMODB_ENDPOINT_OVERRIDE=http://localhost:8100 ./gradlew bootRun --args='--server.port=3100 --spring.docker.compose.enabled=false'`.
