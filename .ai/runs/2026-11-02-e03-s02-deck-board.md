# Execution plan: E03-S02 — Deck and System details show the shared board

Source doc: .ai/specs/2026-10-29-e03-bidding-phase.md
Issue: #37

## Goal

A player in a running game sees the shared board: the Deck (s01) with the six-system hexagon map, each
system's goods, prices and market labels, ships under each system and "Your fleet" with cargo; and System
details (s02) with locations, market and market positions. The loading (s06), not-a-player (s07),
unknown-screen (s08) and stale-poll states behave as S02-9…12 say.

## Scope

- `game` domain: `Ship.cargo` (goods → units) with `cargoSpacesUsed()` (R42: only POLY and ISO take
  space); `Player.marketPositions` (system, goods, tier — R28; everyone starts with none, R40).
- `trading.StarSystem`: R31 location statistics (Port class and legal system, Space police, Planet security).
- `game` DynamoDB adapter: `ShipItem` stores `cargo`, `PlayerItem` stores `marketPositions`; both default
  to empty for older items (§12, `BACKWARD_COMPATIBILITY.md` §7).
- `game` web adapter: the game shape gains `board` (the six systems with their locations and market),
  `players[].marketPositions` (public, R28) and `you.ships` (the caller's own ships with cargo — other
  players' cargo is never sent, S02-7, A05).
- `static/js/board.js` (new, pure, unit-tested): market level from buy chance (D08), map layout, initials,
  fleet and cargo lines, routes, stale-poll text.
- `static/index.html`: the running-game view becomes the Deck (s01); new System details view (s02);
  s07 and s08 panels; the stale-poll notice with **Retry now**.
- `BACKWARD_COMPATIBILITY.md` §6 and §7; `docs/design-system.md` (market-level colour mapping).

## Non-goals

- Offer form, "Your offers", initiative bid (S03, S05); "I'm done bidding" and the waiting list (S04);
  the Game log screen s04 (S06) — the existing log panel stays on the Deck until S06 replaces it.
- Anything that fills cargo or changes market positions (E05). This story only carries and shows them.
- Changing prices per game (E05): the board is still the fixed `StarSystem` table, sent per game so E05
  can make it per game without changing the shape.
- The fifth market colour in the design system (spec out of scope, D08 follow-up), and the fixed-width
  sidebar overflow at 320 px (known design-system gap).
- The old home "Market Overview" (`/api/options`) and `trade-offers.html`.

## Decisions

- Base branch `main` (config `auto` resolves to the default branch).
- **Market label is computed in the client** (`board.js`), from the S/D number the server sends: it's a
  presentation of D08, and arrows/hints are UI copy. The moderate/high demand split is the exported setting
  `MODERATE_DEMAND_MIN_CHANCE = 0.20` (S02-3).
- **Colours without a new token** (the fifth colour is out of scope): high supply `--sd-easy`, moderate
  supply `--sd-fair`, in balance `--text-muted`, moderate demand `--sd-hard`, high demand `--sd-bad`. The
  arrow and the label word carry the meaning; colour is never the only cue.
- **Cargo is private**: it goes in `you.ships`, not in public `players[].ships`. The spec says other
  players' cargo is never shown; not sending it is the A05 way to guarantee that. Denied-path test required.
- **Market positions are public** (R28: "shown on the system screen"), so they go on `players[]`.
- **R31 numbers** are the prototype's values (the brief fixes no numbers; "numbers only, no mechanics").
- **Routes**: `#game/{id}` is s01, `#game/{id}/system/{SYSTEM}` is s02 (the `StarSystem` constant). `''`,
  `#new` as today. Any other fragment is s08, linking to the Deck.
- **s07 vs the lobby invite**: a `403` can't tell a lobby from a running game without leaking state (A05),
  so the 403 panel is headed "You're not a player in this game" (S02-10) and keeps E02-S05's **Join this
  game** button with "If the game hasn't started yet, you can join it." A join on a running game shows the
  server's "This game has already started".
- **Stale poll**: "Couldn't refresh the game. Showing the state from N seconds ago." with **Retry now**;
  N is rewritten on each failed poll, not ticked every second (design system A04: no live counters).

- **Persistence lands with the domain field** (steps 1.1, 1.2 also do 2.1): §12 makes a new domain field fail to
  compile until its item class reads it, so the item change can't be a separate commit.

- **Narrow screens** (found in the browser walk): with the fixed 220 px rail the map was ~100 px wide at 390 px.
  Below 700 px the rail now stacks above the screen. The map's text still scales under the 12 px floor on a
  phone; recorded as a design-system gap rather than solved here.

- **Review fixes** (om-auto-review-pr on #70, def99a7): unknown system no longer re-polls and steals focus;
  the stale notice announces once; a lobby no longer leaves a pending System-details focus.

## Risks

- `risk-high` (issue label): the cargo split is a confidential-read check; covered by a controller test
  proving another player's response never carries it.
- Adding stored attributes: older items must read as empty (round-trip + missing-attribute tests).
- `index.html` grows; keep logic in `board.js` so it stays testable.

## Implementation Plan

### Phase 1: Domain

- 1.1 `Ship.cargo` and `cargoSpacesUsed()` (R42), TDD.
- 1.2 `Player.marketPositions` with `MarketPosition(system, goods, tier)` and `MarketTier` (R28).
- 1.3 R31 location statistics on `StarSystem`.

### Phase 2: Persistence and API

- 2.1 `ShipItem` cargo and `PlayerItem` market positions, with defaults for older items and round-trip tests.
- 2.2 Game shape: `board`, `players[].marketPositions`, `you.ships` with cargo; controller test that another player's cargo is never sent.
- 2.3 `BACKWARD_COMPATIBILITY.md` §6 and §7.

### Phase 3: Client logic

- 3.1 `board.js`: buy chance, market level, arrow, hint and colour step (D08), with tests.
- 3.2 `board.js`: routes (s01, s02, s08), initials, ships-under-system text, fleet and cargo lines, stale text, with tests.

### Phase 4: Screens

- 4.1 Deck (s01): top bar, map with legend, ships under each system, Your fleet, log panel.
- 4.2 System details (s02): three foldable sections, empty states, heading focus.
- 4.3 States: s06 loading, s07 not a player, s08 unknown screen, stale poll with Retry now.
- 4.4 `docs/design-system.md`: market-level mapping and the board components.

### Phase 5: Verification

- 5.1 Full gate (`./gradlew build`) and a browser walk of s01, s02, s06–s08 and the stale state, with screenshots.
