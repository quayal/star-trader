# Execution plan: E04-S02 — Players jump their ships in turn order

Source doc: .ai/specs/2026-10-29-e04-ship-jumps-phase.md
Issue: #43

## Goal

Once the turn order is set (E04-S01), each player in turn order gets a slot: they jump their ships one at a time to
any other system, each ship at most once per turn, until they've jumped every ship or press **Finish jumping**. Every
jump is public: the map, s02 and the Game log show it at the next poll. After the last slot the phase moves to Trading.

## Scope

- `game` domain: `Turn.jumpedShips` (names of ships that jumped this turn) and `Turn.doneJumping` (emails whose slot
  has ended, in order), both public and reset with the turn. `Turn.jumper()` gives whose slot it is.
  `Game.jumpShip(email, shipName, destination)` and `Game.finishJumping(email)` apply the S02 rules, log each jump
  ("Jump: {corp} — {ship} → {system}", S02-7), end the slot on the last ship (S02-6) and move to Trading after the
  last slot (S02-8).
- `ShipJumpsService.jump` / `finishJumping` inside `GameStore.update` (atomic, A04).
- DynamoDB: `TurnItem.jumpedShips`, `TurnItem.doneJumping`; older items read as none.
- Web: `POST /api/games/{id}/ship-jumps/jumps` `{ ship, destination }` and `POST /api/games/{id}/ship-jumps/finish`,
  both `200` + the game; `turn.jumpedShips` and `turn.doneJumping` in the game.
- `static/js/ship-jumps.js` (new, pure, unit-tested): whose slot it is, the top-bar text, each turn-order slot's
  status ("jumping now" / "done"), the ships you can still jump, the same-system check.
- `static/index.html`: top bar "— {corp} is jumping" / "— your jumps" / "— all jumps done"; Turn order rows gain the
  slot status; right column "Your next jump" (ship, destination, **Jump**, **Finish jumping**) during your slot,
  with the inline same-system error focused on the destination.
- `BACKWARD_COMPATIBILITY.md` §6 and §7.

## Non-goals

- The landing dialog (S03). Until it ships, a ship that jumps arrives in Space (see Decisions).
- Anything in Trading (E05). After the last slot a game waits in Trading, as it already does for Ship-jumps today.
- A separate live-progress story (S04) beyond what polling already redraws.

## Decisions

- Base branch `main` (config `auto`).
- **A jumping ship arrives in Space.** It has left its old Port/Planet; S03 then asks where it ends up (Escape =
  stay in space, S03-2). R31: locations have no mechanics in v1, so nothing else depends on it meanwhile.
- **Jumped ships stored by name.** Ship names are unique in a game (`Ship.NAMES`, two per player), so
  `jumpedShips` needs no owner.
- **Whose slot it is** is the first player in turn order not in `doneJumping`, derived, never stored; the client
  derives it the same way from `turn.turnOrder` and `turn.doneJumping`.
- **Refusals**: out of turn → `409` "It's {corp}'s turn to jump."; the turn order not set yet → `409` "The turn order
  isn't set yet."; Bidding → `409` "Ship-jumps hasn't started."; after Ship-jumps → `409` "Ship-jumps has closed";
  an unknown, someone else's or already-jumped ship → `400` "Choose one of your ships that hasn't jumped this turn.";
  missing/unknown destination → `400` "Choose a destination system."; same system → `400` "{ship} is already at
  {system}. Pick another destination." (S02-4).
- **"all jumps done"** (S02-1) is shown when the order is set and nobody is left to jump; since the phase moves to
  Trading at that moment (S02-8), it's a fallback text rather than a state players sit in.
- **Cargo stays private** (S02-10, R29): `players[].ships` already carries no cargo; a controller test pins it after a
  jump.

## Risks

- `risk-medium`: two new stored attributes, two endpoints with an ordering rule and a phase change. Covered by domain
  tests (whose slot, out of turn, each refusal, last-ship slot end, Trading after the last slot, logs), persistence
  round-trip and older-item tests, controller tests per status, a replayed-update test, and JS unit tests.
