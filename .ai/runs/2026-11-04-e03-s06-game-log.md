# Execution plan: E03-S06 — Players read public events in the Game log

Source doc: .ai/specs/2026-10-29-e03-bidding-phase.md
Issue: #41

## Goal

The Game log (s04) is its own screen: the game's public events grouped by turn, newest turn first, each turn
foldable, never carrying offers, bids, money or anything else confidential (R17, R29), and "No public events yet."
when there's nothing to show.

## Scope

- `game` domain: `LogEntry(turn, text)`; `Game.log` becomes `List<LogEntry>`. The start's two lines belong to turn 1,
  the initiative line to the turn whose Bidding closed.
- DynamoDB: `log` stores `{ turn: N, text: S }` maps through a new `LogEntryItem`; an older item's plain string
  entries read as turn 1.
- Web: the game shape's `log` becomes `[{ turn, text }]` (`LogEntryResponseDto`). Denied-path test: no bid amount
  or money reaches the log (S06-3).
- `static/js/log.js` (new, pure, unit-tested): turn grouping (newest turn first, events oldest first within a turn)
  and the empty text. `game.js`: the `#game/{id}/log` route and `logLink`.
- `static/index.html`: s04 — a "Game log" sidebar item while a game is open, the screen with one `<details>` per
  turn, fold state kept across polls; the Deck's flat log panel goes (the S02 plan left it there until S06).
- `BACKWARD_COMPATIBILITY.md` §6 and §7.

## Non-goals

- E04/E05's events (turn order, jumps, landings, trading order, resolved trades): they add their own lines.
- Any change to what the existing lines say.
- A "Game over" line (E05-S08).

## Decisions

- Base branch `main` (config `auto`).
- **The start's lines stay in the log, under turn 1.** "Game started" and "Starting positions" are public (ships are
  on the map for everyone) and E02-S05 put them there. So a started game's log is never empty; "No public events
  yet." shows whenever there are no entries (S06-4's wording, kept). Turn 1 therefore reads: game started, starting
  positions, then the initiative order once Bidding closes.
- **`log` changes shape (`[string]` → `[{ turn, text }]`)** rather than adding a parallel field: the only consumer is
  `index.html`, updated in this PR (BACKWARD_COMPATIBILITY §4, §6). Stated in the PR body.
- **Older stored entries read as turn 1**, so no local data needs clearing. Only games played with E03-S05 (merged
  today) past turn 1 have a later line, which then sits under turn 1; that's local test data only.
- **Fold state survives a poll**: a turn the player folded stays folded when the log redraws, keyed by game and turn
  (lesson 2026-11-04). New turns open unfolded.
- **Steps 1.1, 1.2 and 2.1 landed in one commit**: the response DTO reads `Game.log`, so the new type doesn't compile
  until the DTO maps it (as in E03-S05).
- **The top bar on s04** shows turn, phase, money and initiative like s01, without "I'm done bidding" (S04-1 puts
  that on s01/s02).

## Risks

- `risk-medium`: a stored-shape and API-shape change. Covered by `LogEntryItem` round-trip and older-item tests,
  `GameItemTest`, and `GameControllerTest`'s shape assertions.
- R17/R29: the log is built only from public lines; a controller test checks a closed Bidding's log has no amounts.
