# Execution plan: E01-S01-T01 — send the one-time code by email (Resend)

Source doc: .ai/specs/2026-10-25-e01-s01-t01-transactional-email-provider.md
Issue: #13

## Goal

A player receives their one-time sign-in code by email, sent through Resend
behind the existing `OneTimeCodeSender` port, so remote players can sign in
(A02, D03; the first playtest needs it, per E01-S03 criterion 7).

## Scope

- `login/adapter/email`: `ResendOneTimeCodeSender` replaces `LoggingOneTimeCodeSender`.
- `login`: `OneTimeCodeDeliveryException`; `LoginController` maps it to `503`.
- `application.properties`: Resend API key and sender address from the environment.

## Non-goals

- Resend domain verification (an operational step for the creator, spec Step 0).
- Running the live send in CI; retries or queueing; rate limiting (brief: Later).

## Deviations from the spec, recorded

Two decisions made after the spec (2026-10-25) supersede two of its autonomous defaults:

- **A failed send throws instead of being swallowed (spec Q3).** The 2026-10-28
  hardening sends before storing "so a failed send keeps the player's previous
  code", which only works when the sender throws. E01-S03's sign-in spec (2026-10-29)
  shows "We couldn't send the code. Try again." on delivery failure. So the adapter
  throws `OneTimeCodeDeliveryException` and `POST /api/login/request-code` answers
  `503` with that message. Resend's errors are not passed through, so nothing about
  the address is revealed.
- **No code logging under `prod` (spec Q2).** The hardening disables code logging
  under the `prod` profile. Without Resend configured, the adapter logs the code
  outside `prod` (as today) and refuses to start under `prod`.

## Implementation Plan

### Phase 1: Real email delivery

1. Resend properties in `application.properties`.
2. `ResendOneTimeCodeSender` (RestClient POST to `https://api.resend.com/emails`;
   log fallback outside `prod`; startup failure under `prod` when unconfigured;
   `OneTimeCodeDeliveryException` on any Resend error); remove `LoggingOneTimeCodeSender`.
3. `ResendOneTimeCodeSenderTest` with `MockRestServiceServer`: request body and
   headers; error response → exception, key never logged; unconfigured → no HTTP
   call; unconfigured under `prod` → construction fails.
4. `request-code` maps a delivery failure to `503`: controller test with a failing sender.
5. `ResendOneTimeCodeSenderLiveIT`, opt-in via `RESEND_API_KEY` (skipped otherwise).
6. Full gate: `./gradlew build`.

## Risks

- `RESEND_API_KEY` is a secret: read from the environment only, never logged or committed.
- `request-code` gains a `503`, a contract addition the sign-in screen (E01-S03) consumes.
- The live proof of A02 needs the creator's verified domain and a real inbox; it's a
  manual step recorded in the PR, not something CI can show.
